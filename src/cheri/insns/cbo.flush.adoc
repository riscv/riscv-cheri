==== CBO.FLUSH ({cheri_base_ext_name})

Synopsis::
Perform a flush operation on a cache block

Mnemonic::
`CBO.FLUSH 0({cs1})`

Encoding::
[wavedrom, ,svg,subs=attributes+]
....
{reg: [
  {bits: 7,  name: 'opcode',    attr: ['7','MISC-MEM=0001111'],  type: 8},
  {bits: 5,  name: 'funct5',    attr: ['5','CBO=00000'],     type: 2},
  {bits: 3,  name: 'funct3',    attr: ['3','CBO=010'],  type: 8},
  {bits: 5,  name: 'rs1{ne}0',  attr: ['5','base'],     type: 4},
  {bits: 12, name: 'funct12',   attr: ['12','CBO.FLUSH=000000000010'],   type: 3},
]}
....

include::load_store_creg0.adoc[]

Description::
A CBO.FLUSH instruction performs a flush operation on the cache block whose effective address is the base address specified in `{cs1}`.
The authorizing capability for this operation is `{cs1}`.
+
This instruction requires that `{cs1}` grants <<r_perm>> and <<w_perm>> and that at least one byte of the cache block is within the bounds of `{cs1}`.
+
NOTE: CBO.FLUSH only requires one byte of the cache block to be within the bounds of `{cs1}` so software can flush all cache blocks covering a memory buffer even when the buffer is not cache-block aligned.
Even though data is not modified by CBO.FLUSH, requiring bounds and permission checks helps mitigate cache timing side channels.
